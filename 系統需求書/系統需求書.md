# 全自動有聲小說系統需求書

版本基準：2026-08-22 現行程式碼
適用範圍：本儲存庫的本地製作、GitHub Actions 雲端製作及 YouTube 發布流程

本資料夾是系統的可實作規格（implementation specification）。開發者應能只依本需求書重建相同行為；若文件與程式發生衝突，以本頁標示的版本基準程式為現況證據，並在變更程式時同步修改相應章節。

## 一句話架構

GUI 將一或多個目錄網址寫入 GitHub 持久化佇列；短時調度器一次只啟動一部小說。worker 逐章產製後，發布程序依 10～11 小時規劃 Part，將同一份 MP4、YouTube SRT、總封面與合併索引完整備份至 Hugging Face，同時發布 YouTube；兩邊均驗證完成才清理暫存並啟動下一部小說。

## 規範用語

- 「必須／不得」是驗收條件。
- 「應」是強烈要求；偏離時必須在變更說明中記錄理由。
- 「現行」描述 2026-08-11 程式實際行為。
- 「目標」描述已知應修正但尚未由現行程式完整實現的行為；不得誤寫為已完成。

## 核心不可破壞條件

- 正式流程不得生成、讀取或依賴章節摘要，也不得引入 Torch、Transformers、Qwen 等摘要模型依賴。
- 新任務 Edge-TTS 使用 `zh-CN-YunxiNeural`、`+50%`；舊設定缺少 `edge_rate` 時回退 `+0%`。
- 每章只有通過內容驗證的 RawText、CleanText、WAV、SRT、JPG、MP4 才可寫成完成狀態。
- 每書 Cleaner 刪除設定一律為純文字；特殊符號不得作為正則語法，GUI 預覽與正式 Cleaner 必須共用同一清洗函式。
- 任一 worker 尚有不完整章節時，整體 worker 必須失敗，且不得進入發布。
- YouTube Part 只有在影片、縮圖、CC 字幕、播放清單位置、隱私狀態均確認後才算完成。
- Hugging Face Part 只有在 MP4、同版 YouTube SRT、manifest、media info 與全書總封面均可回讀後才算完成。
- YouTube 與 Hugging Face 可並行上傳；任一邊未完成均不得清理 Part MP4 或釋放佇列給下一部小說。
- `waiting_retry`（包含 YouTube 配額）必須阻擋下一部小說，並在 `retry_at` 後從同一 checkpoint 續作。
- 未取得 YouTube Video ID 前不得刪除來源檔；可續傳錯誤不得造成重複上傳。
- 全書共用唯一無文字 `master_cover.jpg`；Part 封面只能由它疊字衍生。
- 「使用者最後看到的播放清單」是不可繞過的最後驗收關：必須恰好由第 1 部排到最後一部、沒有遺漏或重複，且所有 Part 必須具有同一個封面 SHA-256 證據。若封面有差異，必須以最後一部封面覆蓋每一部影片後再驗收；否則 workflow 必須失敗。
- 播放清單只有在全部 Part 完成並通過最終驗收後，才可依全部影片實測秒數總和改名為 `[已完結]《小說名稱》XX小時 全集`；`XX` 為捨去小數且不補前導零的整數小時，禁止預估或瞎填。
